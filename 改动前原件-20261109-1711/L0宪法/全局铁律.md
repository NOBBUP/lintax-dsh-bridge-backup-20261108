| # | 禁止行为 | 判据 |

### 判断三问（动手前必答）

```
① 这件事有现成的吗？          → 有 ⇒ 复用，不造
② 宿主明确让我做这件事了吗？    → 没有 ⇒ 只写请求，不动手
③ 做完会不会碰到"我没被要求碰"的东西？ → 会 ⇒ 先问
```

> **三问有一问答不上来 ⇒ 停下来问，不要先斩后奏。**

## §3 单一真源

> **每个东西只属于一层，只在一个地方是"真源"；其他地方只放指针。**

| 层 | 存什么 | 只读还是只写 |
|---|---|---|
| L0 宪法 | 铁律与附则 | 只读（宿主独占写） |
| L1 共享层 | 台账 / 看板 / 索引 / 体检 | 分区写，各 owner 只写自己的 |
| L2 场景私有 | 结论与交接 | 只有本场景 |
| L3 个人层 | 个人档案与知识库 | 只有本人与授权者，⛔ 不进共享层 |
| L4 运行时 | 引擎 / 外壳 / 工具 / 技能 | 由专人维护；工具放代码仓外 |
| L5 归档 | 备份 / 冷备 / 可回滚 | 只进不改 |
| **L6 沉淀** | **全量对话原始记录** | **只进不出；"历史原文"的唯一真源** |

**同一事实存两处 = 病**（"记忆说 A、台账说 B"）。发现两处打架 ⇒ 找出真源，另一处改成指针。

### ⛔ 为什么弃用「上下文百分比」—— 实测证据（2026-11-02）

| 观测 | 数据 | 结论 |
|---|---|---|
| 15 个会话的 `contextWindow` | **全部 = 300000**，一个不差 | 这是 DSH 写死的假设值，不是模型真实窗口 |
| 模型真实窗口差异 | `deepseek-v4.1-flash` 300k / `kimi-k3-2` **1000k** / `deepseek-v3-2-volc` **96k** | 一个分母套所有模型，必然错 |
| 命令场景本会话 | **122%（365k/300k）仍在正常跑** | 超 100% 不报错 ⇒ 不是硬限制 |
| 崩掉那次（真事） | `prompt is too long: 1048602 tokens > 1048576 maximum` | 真窗口是 **1M**，不是 300k |

**结论：`contextWindow: 300000` 是假设值。**
但**百分比可以当"占位符"用，绝对值不能靠猜**：
现在两处都写进 `L1共享层\_共享记忆\命令台\水位阈值.json`
（`red: 180000` + `redPct: 0.6`），窗口一变就改 pct，不用重算绝对值。

```
            （结论 / 证据 / 下一步 / 卡点 → §〇 与 §五，规则见 §4.1~§4.6）
              ↓  这一步没做，不许压缩
② 压缩  —— /compact（引擎自带：Compact older conversation history）
              ↓
③ 复验  —— 真实成本 tok 前后对比，写进日志（⛔ 不看 %、⛔ 不看 MB）
```

**⛔ 顺序反了没用**：先压缩，摘要里就只剩"它想留下的"，你要保的东西已经没了。

### 硬规矩

| # | 规矩 | 判据 |
|---|---|---|
| 1 | **三条线都看真实成本 tok** | ⛔ 不看文件 MB（负相关 −0.380）；⛔ 不看百分比（分母是假设值） |
| 2 | **压缩前必须先落盘** | §〇 里能读到"本轮做了什么 / 下一步 / 卡点"，才允许 `/compact` |
| 3 | **只记结论，不搬对话** | 写回 ≤10 行 / ≤2 KB；⛔ 不把聊天原文抄进记忆 |
| 4 | **跨场景通用的才进共享层** | 只对某场景有用的留在 L2；别的场景也用得上的才写 `L1共享层\_共享记忆\`（§3 单一真源） |
| 5 | **压缩不降文件体积，但降 tok** | 实测压缩后 1.87 MB → 1.88 MB（日志只追加）；但 tok 会真掉（135%→7%）⇒ **体积和成本是两件事** |
| 6 | **180k 就开始写收尾** | ⛔ 不许贴到 90% 才动 —— 到线就停新活、写 §〇 |

### 为什么必须"先落盘再压缩"

`/compact` 把较早的对话**压成一段摘要**，细节不可逆地消失。摘要由模型自己决定留什么 ——
它不欠你任何东西。**唯一能保证不丢的，是压缩前已经写在磁盘上的字。**

### 机械抓手（怎么落地，不靠自觉）

```bash
# ① 先落盘体检 —— 不过就不许压（会检查 §〇 是否本轮写过，并复制一份托底快照）
node 工具\压缩前落盘.mjs
node 工具\压缩前落盘.mjs --看          # 只看，不改文件

# ② 再压缩（会话不能压正在运行的自己，脚本会等它空闲）
node 工具\压缩我的会话.mjs <自己的 sessionId> --最多等 600

# 只看当前大小 / 百分比，不动手
node 工具\压缩我的会话.mjs --看 <sessionId>
```

**`压缩前落盘.mjs` 做三件事，不做第四件：**
- ① **体检**：§〇 在 `--新鲜`（默认 30 分钟）内改过 ⇒ 算落盘过了；否则 **exit 1 拒绝放行**
- ② **托底快照**：把记忆原文复制进 `场景记忆\归档\压缩前快照-<时间>.md`（⛔ 不改正文一个字）
- ③ **记审计**：`引擎\.tmp\compact-audit.log` 追加一行（谁 / 何时 / MB / 是否放行）
- ⛔ **它不替你写记忆内容** —— 判断"什么关键"是会话自己的活，机器抽出来的"结论"必然是垃圾

> **§9 校验必须能失败**：这个工具已实测负例 ——
> `--场景 不存在的场景XYZ` ⇒ exit 2「认不出我是哪个场景」；
> 记忆 30 分钟没动过 ⇒ exit 1「⛔ 不许压缩」。**它会失败，所以它不是装饰品。**

- **哨兵会自动提醒**：`工具\会话哨兵.mjs` 每 **180 秒**（3 分钟）扫一次 `session/list` 的 `contextPressure`。
- **⚠ 会话不能压缩正在运行的自己**：引擎硬限制
  `Compaction is unavailable because this process has an active compaction, or the agent is not idle.`
  ⇒ 必须由**外部进程**等它 `running=false` 后调 `commands/execute {line:"/compact"}`。
  `压缩我的会话.mjs` 就是干这个的。

### ⭐ 第 6 条硬规矩：**提醒只在人家停手之后出现**（2026-11-02 宿主定）

> 宿主原话：「**哨兵不要那么频繁，压缩上下文等别人思考完了再说呀**」

| 消息 | 只在什么时候提 | 为什么 |
|---|---|---|
| **催促进度 / 疑似卡死** | `running = true` 时 | 这是"你在跑"，得压它快点交东西（见第 7 条） |
| **压缩提醒** | `running = false` 时 | 引擎本来就压不了运行中的自己；人家正在解题，塞一句"去压缩"只能回"稍后"，纯打断 |
| **收尾预警 / 换会话** | `running = false` 时 | 同一个道理：这是"你干完了，该做个体检"，不是"你干活时该想的" |

**正在干活但已过线的 ⇒ 只排队，不打断**（日志里记 `⏸ 排队（等它停手再提）`，等它那一轮 `running` 变 false 自动补推）。

**频率硬限制**（防止一条提醒反复轰炸）：

| 提醒 | 最短重提间隔 |
|---|---|
| 压缩 | **6 小时**（或上下文又涨 ≥10 个点） |
| 收尾预警 | 12 小时 |
| 换会话 | 6 小时 |

**另外**：轮询从 60 秒拉到 **180 秒**；"我在岗"只在**30 分钟没别的话可说**时自报一行，不再每轮刷屏；
**已归档的会话一律不推**（没人能执行，纯噪音）。

> 反面教材（我自己犯的）：旧哨兵每 60 秒一轮、每次只要有会话在思考就打一行
> `🔥 思考中：某某(38%, 思考480s)` —— 一小时 60 行全是废话；
> 而且它把"该压缩了"推给 `running=true` 的会话，人家正在解题被塞一句，只能说"稍后"。
> 宿主当天就点了出来：「**压缩上下文等别人思考完了再说呀**」。

### ⭐ 第 7 条硬规矩：**催促 = 问进度 + 请加速 + 让它自评**（2026-11-02 宿主两次纠正后定稿）

> 宿主原话①（第 1 次）：「**10分钟催促指令本质目的是催促而不是查看对方是否死机；要催促他加快进度**」
> 宿主原话②（第 2 次，纠正我写坏的文案）：
> 「命令不是这么用的，你就这样子说：**已经10分钟，进度如何，催促一下**」
> 「**20分钟就：20分钟了，麻烦加快进度**」
> 「**30分钟再说进度如何，让场景回复进度，因为有些东西就是要很长时间的，让场景自己评估下难易度实现程度预计时间，而不是直接最小可行版本，这样子其实不好**」

**三次纠正的教训：**
- 第 1 版写成「说清卡在哪」⇒ 查户口式，错。
- 第 2 版写成「别往下铺了 / 只做最小可用版本 / 停止推进收口」⇒ **越权替场景砍需求**，更错。
  长任务是正常的；逼它交半成品只会毁掉正经活。

**定稿：三档，每档只做一件事，10 / 20 / 30 分钟各一次，之后不再催。**

| 档 | 触发 | 原话（照这个语气，别加工） |
|---|---|---|
| **1 档 · 问进度** | 10 分钟 | 「已经 10 分钟了，**进度如何**？」+ 接着做，有卡点说一声 |
| **2 档 · 请加速** | 20 分钟 | 「20 分钟了，**麻烦加快进度**」+ 碰到绕不过去的坎直接说 |
| **3 档 · 让它自评** | 30 分钟 | 「说一下现在的进度：① 做到哪一步 ② 还剩什么 ③ **难易度 / 你估计还要多久** ④ 需要我协调什么」+ **「长任务我理解，我要的是你的判断，不是让你砍需求」** |

**⛔ 三条禁令（写死在自测里，任何一档出现就判失败）：**

| 禁止的话 | 为什么 |
|---|---|
| 「只做最小可用版本」「先交一半」「哪怕只覆盖一半」 | 把正经活逼成半成品 |
| 「别往下铺了」「砍掉附加功能」 | 越权替场景决定范围 |
| 「收口」「停止推进」「停止推进按现状收尾」 | 30 分钟不是让项目下马的理由 |

**⛔ 30 分钟档之后不再催**（同一轮里翻来覆去催会毁掉思路）。之后只保留「疑似卡死」兜底。

**「疑似卡死」是副线，三个条件缺一不可：**
1. **已经催过**（`nudgedAt` 有值）—— 没催过就不查尸，先催；
2. 催完之后**又**过了 `--卡死`（默认 10 分钟）；
3. 这段静止**发生在催促之前**（催完还有动作 ⇒ 说明它在动，不是卡死）。

> 顺序反了就是灾难：10 分钟一到两条一起推，人家收到的第一句是「你是不是挂了」。
> 而且实测证明——它没挂，它只是慢。**催，不等于怀疑；催，也不等于替它砍需求。**

**判据有自测**（`node 工具\会话哨兵.mjs --自测`，**26 条断言**）：
- 档位/封顶/副线三条件（15 条）
- **文案 11 条**：1 档必须有「进度如何」、2 档必须有「麻烦加快进度」、3 档必须有「难易度 / 还要多久 / 已经做到哪一步 / 长任务我理解」，
  且**任何一档都不许出现**「最小可用」「先交/交一半/覆盖一半/哪怕只」「别往下铺」「收口/停止推进」
> 判据抽成纯函数 `nudgeTierFor()` / `nudgeText()` / `shouldReportStall()` 才测得出。
> 之前用"伪造 state 跑真进程"测，实时快照会盖掉伪造值 ⇒ 测了个寂寞。

### ⭐ 第 8 条硬规矩：**压缩 / 收尾 / 换会话是机械操作，⛔ 不许走 AI 思考**（2026-11-02 宿主定）

> 宿主原话：「**场景压缩个上下文或者换会话怎么要思考这么久？
> 不是一分钟之内就能确定如何操作然后快速结束吗？运维那个场景都思考十分钟了，这也太慢了吧**」

**根因（我设计的错）**：老哨兵发现超线后**推一条消息给 AI**，然后 AI 读消息→想→跑脚本→想→验→回话，
每一步都是一次完整 LLM 往返 ⇒ 光"想"就 1~2 分钟 × 4~5 步 = **10 分钟**做一件机械活。

**正确分工（已实现）：**

| 动作 | 谁执行 | 为什么 |
|---|---|---|
| **压缩** | **哨兵自己**直接调 `commands/execute {line:"/compact"}` | 纯机械，引擎有现成命令，不需要任何判断 |
| **换会话** | **哨兵自己**直接跑 `外壳\scripts\换会话.mjs <面板id> --force --go` | 建会话→归档→回写 json→开场消息，脚本全包 |
| **写 §〇**（进度/下一步/卡点） | **场景自己**，在**收尾线（180k tok）**时写 | 这是唯一需要"知道自己在干什么"的一步，但不能拖到兜底交接线才写 |

**⛔ 三条禁令：**

1. **不许把机械操作包装成"提醒"再让 AI 走一遍** —— 那是 10 分钟换 10 秒。
2. **不许让 AI 判断"要不要压缩"** —— 成本到 120k tok 就压，没有判断空间。
3. **§〇 必须在收尾线（180k tok）就写好**，不许到兜底交接线才想起来写，
   否则换会话会被脚本拒绝（"交接太旧"），又得等一轮 AI 往返。

**自测判据**：哨兵日志里出现 `⤵ 自动压缩 → 场景  166k → 12k tok ✓` 才算生效；
出现「该压缩了，请你自己跑…」这种转述文案就是退回老路了。

### ⭐ 第 9 条硬规矩：**会话压不了自己 —— 压缩必须由外部进程做**（2026-11-02 宿主截图实证）

> 宿主原话：「**这是客户系统运维场景，思考了十几分钟得出这么一个结论，哨兵呢？交接一下啊**」

**事故现场（客户系统运维，99% / 1.38 MB）：**
它照着提示跑 `压缩我的会话.mjs`，脚本等这条会话 `running=false`，
**但脚本就跑在这条会话里** ⇒ 该会话永远 `running=true` ⇒ 等了 600 秒、40 次轮询全 `true`，最后放弃。
**思考 13 分钟，产出是一个"压缩失败"的结论。**

**根因：这不是 bug，是物理必然。**
一个进程不可能"在执行脚本的同时处于空闲"。**自己压自己，等一万年也不会成功。**

| 谁执行 | 结果 |
|---|---|
| 场景自己在会话里跑 | ❌ **永远 running=true，必然等满超时** |
| **哨兵**（独立进程，不在任何会话里） | ✅ **等待 0 秒就压成功**（实测：1.38 MB / 99% → 1% 耗时 30 秒） |
| 宿主在终端手动跑 | ✅ 可以 |

**⛔ 三条硬规定：**

1. **会话不许自己跑压缩** —— `压缩我的会话.mjs` 现在会检查 `DSH_SESSION_ID`，
   发现"要压的就是我自己"时**立刻 exit 3 并说明原因**，不再白等 600 秒。
2. **压缩一律由哨兵做** —— 哨兵是独立进程，每 3 分钟一轮，撞到 `running=false` 的空隙就压。
3. **抢救式压缩**：只要成本 ≥ 压缩线就压，**不等收尾线/交接线** ——
   因为长期 `running` 的会话可能永远等不到那些线。同一会话 30 分钟内只抢救一次。

**验收证据（2026-11-02 11:09 实测）：**
```
[11:09:26] 目标 session-66c4bb69…  文件 1.38 MB  上下文 99%（297k/300k）  5 轮  running=false
[11:09:27] ✓ 已空闲（等了 0s），开始 /compact
[11:09:52] ✓ 压缩命令返回：Compacted 477 history items (~295717 tokens).
[11:09:57] 复查：文件 1.38 MB → 1.39 MB   上下文 99% → 1%
```
**30 秒 vs 13 分钟。** 差别只在于"谁来执行"。

### ⭐ 第 10 条硬规矩：**换会话只有一条路 —— 跑 `工具\交接.mjs`**（2026-11-02 宿主定）

> 宿主原话：「**哨兵是独立于会话的，他游走在各个场景包括你，超限则压缩很简单的道理；
> 超过2.4mb就要写好交接换会话；自动执行，不需要对话；
> 换会话所有场景操作如下，接收指令，立即执行宪法层的那个交接mjs文件，
> 然后进行交接操作换会话；旧的会话直接归档进入沉淀层**」

**哨兵的定位（一句话）：独立于任何会话，游走全部 12 个场景，超线就动手，全程不对话。**

| 线 | 哨兵动作 | 谁执行 |
|---|---|---|
| 成本 **≥120k tok**（40% 窗口） | 直接 `commands/execute /compact` | 哨兵（外部进程） |
| 成本 **≥180k tok**（60% 窗口） | 提醒一次「开始写收尾」（写 §〇，**但不换人**） | 场景自己（唯一需要判断的一步） |

**`交接.mjs` 内部就是宿主说的那一套，不用再写第二份：**

```

  ├─ ① 体检：§〇 四小节齐不齐 / ≤4KB / 卡指纹 / 三文档在不在   ← 不过就不换（--force 不免这道）
  ├─ ② 归档副本 + 补 §〇 + 重生成场景画像
  ├─ ③ 调 外壳\scripts\换会话.mjs
  │     └─ 调 外壳\scripts\sessions.mjs --rotate
  │           ├─ 新建同名会话顶上（界面/定位卡/索引都不用改）

  │           ├─ ★ 投 L6 沉淀层（2026-11-02 补：原来 rotate 漏了这一步）
```

**⛔ 三条禁令：**

1. **不许在会话里"问 AI 要不要换人"** —— 只有「会话自己申请」或「压缩过仍 ≥90% 窗口」才换，没有判断空间。
2. **不许绕开 `交接.mjs` 自己写换会话流程** —— 它是唯一入口，重复实现必漏（今天就漏了"投沉淀层"）。
3. **换会话 ≠ 删数据**：旧会话只改名 + 归档 + 入池 L6，**一个字都不删**。

### ⭐ 第 11 条硬规矩：**哨兵的管辖范围包括「命令」自己，无例外**（2026-11-02 宿主定）

> 宿主原话：「**我说了哨兵也参与你这个场景，怎么没有进行？**」

**我犯的错**：老代码写 `rows.filter(r => !r.isSelf && ...)`，把命令自己排除在外。
结果：**命令会话 5.36 MB（165%），远超当时的换会话线，哨兵完全不管。**
宿主的意思很明确 —— 「**哨兵游走各个场景包括你**」，命令不是例外。

| 判据 | 对普通场景 | 对「命令」自己 |
|---|---|---|
| ≥120k tok 压缩 | 哨兵外部进程执行 | ✅ **同样执行**（外部进程压自己完全安全） |
| ≥180k tok 收尾提醒 | 推给场景 | ✅ **同样推** |
| ≥90% 窗口且压缩过仍超 | `交接.mjs --force --go` | ✅ **同样执行**（脚本内有 `stopActivity` 重试） |

**为什么安全**：换自己只在**这一轮说完之后**发生 ——
哨兵只在 `running=false` 时动手，而我跑这一轮时 `running=true`（实测确认），
所以它必然撞在轮与轮之间的空档，**不会打断正在生成的内容**。

**⛔ 实现约束**：`live = rows.filter(r => !r.archived)` —— **只排除归档，不排除 isSelf**。
`--看` 里的 `（我）` 只是标签，`running` 显示必须用真实值（原来一律显示"（我）思考中"是假的）。

### ⭐ 第 12 条硬规矩：**交接 = fork 复制自己，⛔ 不是新建一条空会话**（2026-11-02 宿主定 · 本条最重）

**这是本工作台犯过最严重的一次错 —— 我把"交接"做成了"换人"。**

### ⭐ 第 13 条硬规矩：**交接必须"要么完整成功，要么原地不动"**（2026-11-02 宿主定）

> 宿主原话：「**所有场景交接都得是这样，而且不能出bug，交接不能出问题不能崩溃**」

第 12 条解决了"交接 = 换人"，但还不够 —— 交接**中途失败**同样会让人消失
（fork 出了残的、归档了旧的、json 回写了、然后报错）。所以第 13 条定的是**失败时的行为**：

**任何一步不过，都必须回到"什么都没发生"。**

**⛔ 三条顺序铁律（顺序错了就有窗口期，窗口期内崩了人就没了）：**

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **记忆闸必须在"动旧会话"之前** | 原来是 fork → 归档旧的 → 最后才验记忆。若副本是残的，**旧会话已经被归档掉了**，回滚都没得回 |
| 2 | **旧会话必须先确认存在** | 原来不查。json 里写个不存在的 id ⇒ fork 失败 ⇒ 退回建空壳 ⇒ 归档一个不存在的会话 ⇒ **exit 0 报成功**。又一个"看起来成功、其实人没了"的入口 |
| 3 | **归档失败必须改名回滚** | 旧会话已改成「已归档·…」却没真归档 ⇒ 宿主看到两条同名同源，比崩溃更迷惑 |

**现在的执行顺序（写死在 `sessions.mjs`）：**

```
① 查旧会话存在              ← 不存在就 die，一字不动
② session/fork 复制
③ fork 成 ⇒ 改名新会话
④ ★记忆闸（查记忆保全）      ← 不过就 die，【旧会话一个字没动】，面板还绑老的
⑤ 改名旧会话为「已归档·…」    ← 改名失败 ⇒ die，停在这里
⑥ 真归档（带 stopActivity 重试）
⑦ 归档失败 ⇒ 把旧会话名字改回原标题 + failed=true（exit ≠ 0）
⑧ 投 L6 沉淀层 / 回写 json / 同步名册 / --check / 一致性校验
⑨ 收尾再验一次记忆保全
```

### ⭐ 第 14 条硬规矩：**交接的冷却必须记在「面板」上，⛔ 不能记在「会话」上**（2026-11-02 宿主报死循环后定）

> 宿主原话：「**一个会话满了：2.4mb，然后就自动交接换会话了，但是交接完还超然后继续执行了交接，死循环了**」

**这不是"偶尔出错"，是必然发生的结构性死循环。**

| 时刻 | 事件 | 体积 |
|---|---|---|
| 13:44 | 交接 命令 | 4.06 MB → fork 出 **3.22 MB** → 校验判「3.22 ≥ 2.4 早该交接」→ 失败 |
| 13:47 | 重试 | 3.22 MB → fork 出 **3.22 MB** → 同上 → 失败 |
| 14:14 | 重试 | 4.06 MB → fork 出 **3.61 MB** → ✓ 报成功 |
| 14:19 | 新会话 3.61 MB **仍超线**，且新 sessionId 的 state 是空的 ⇒ 又要交接 | **循环** |

**两个根因，缺一不会成环：**

1. **fork 是复制，不是压缩。** 副本天生 ≥ 原会话的 ~79%（实测 3.22/4.06、3.61/4.06）。
   阈值 2.4 MB **低于副本的下限** ⇒ 交出来的东西一出生就超线。
2. **冷却记在 `sessionId` 上，而交接换掉的正是 `sessionId`。**
   旧会话的 `gatedAt` 随旧会话一起归档，新会话拿到的是**干净 state** ⇒ 冷却永远归零
   ⇒ 同一分钟里可以无限交接。

**正解：冷却键改成 `panel:<面板id>`。**

- 面板是恒定的（`cmd-chat` 永远是 `cmd-chat`），会话是会被换掉的
- 换完之后，同一面板 **6 小时内不许再交接** —— 不管新会话多大
- 大会话不会因此被永久锁死：6 小时后照样能换

**判据（不许删）：** `node 工具\交接死循环自测.mjs` —— **必须 16/16**。

```
【4】连续 10 轮模拟：必须收敛，不能无限循环
  ✓ 连续 10 轮只交接 1 次
【4b】反向验证：如果冷却记在 sessionId 上
  ✓ 反复交接 5 次才停 —— 这就是宿主看到的"死循环"
```

**★ 这条最该记住的：**
**「治病的动作会重置治病的证据」这种设计，天生就是死循环。**
任何"做完就换身份"的操作，它的冷却 / 限流 / 重试计数**必须挂在稳定标识上**，
不能挂在它自己会替换掉的那个 id 上。

**推论（对所有场景适用）：**
- 交接冷却 → `panel:<id>` ✅ / `sessionId` ❌
- 重试计数 → 任务 id / 项目 id ✅ / 每次新建的临时 id ❌
- 限流 → 账号 / IP / 面板 ✅ / 请求 id ❌

> `≥窗口 90% 且压缩过仍超` ⇒ 兜底交接。
> ⛔「30 万窗口」是假设值，详见 §4.7 的实测证据表。

### ⭐ 核心资产不是会话，是这四样

|---|---|---|
| **场景私有记忆** | 做过什么、学到什么、决策与坑 | ❌ 不会（本地文件） |

**会话 = 耗材。换掉它，四样资产一个字不丢。**
所以「能压就压着干」是常态，「换」只是最后手段。

### 真正的判据（自己体感，别人替不了）

| 信号 | 说明 |
|---|---|
| **思考太久** | 简单事绕很久；反复读同一个文件还没把握 |

**反过来：** 只要思路清楚、知道自己在干什么，**哪怕 300% 也继续干**。

**没人替你判断** —— 换会话是**会话对自己状态的诚实评估**。
装没事继续干 = 产出垃圾；诚实说"我该换了" = 专业。

## §6 协作闭环

### 派单 ≠ 公告

| 类型 | 含义 | 必须怎么做 |
|---|---|---|
| **派单** | 要对方**动手** | ⛔ **必须真的投递唤醒**，正文写清"我在等你的回执" |
| **公告 / 知悉** | 只是让对方**知道** | 只落盘，**不唤醒** |

> 判据：句子里有「请你改 / 派单 / 做完回一句 / 改完跑 xxx 复验」 ⇒ 这是派单 ⇒ 必须唤醒。

### 通道不通不派单（守完为主 2026-11-01 定）

> 原话：「守口未回执」「通道没修好之前，停止派单」。
> 依据：定定时发现 11 个场景 0 回执，根因是面板 401 白屏 → 会话进不去 → 派单物理上送不进去。

| 条件 | 行动 |
|---|---|
| 派单通道**未打通**（面板白屏 / 401 / 会话进不去 / `session/prompt` 拒绝） | 【停止派单】不要发。已发的不要催。 |
| 通道打通 | 派单必须**真投递**（`session/prompt`→ `accepted:true`），不是只写记忆文件。 |
| 派单没回执 | 记「未回执」登记到台账，**不要反复催办**。 |

> 判据：【落盘 N/N】不等于【投递成功】。只有对方会话**真的接受了**才算醒了。

## §8 L6 沉淀层（宿主追加的第七层）

> L6 = 全量对话原始记录的沉淀池。**只进不出。**

1. **只进不出**：进 L6 的内容永不删除、永不修改、永不搬走。
2. **只进不出 ≠ 不整理**：索引可重建、派生产物（摘要 / embedding / OCR 文本）可生成，**原始对话文件本体不可动**。
3. **L6 是原料层，不是记忆层**：L6 存"发生过什么"，L1/L2 存"结论是什么"。
   从 L6 发掘出的信息**必须经提炼才可写回上层**，⛔ 不直接覆盖 L2。
4. **发明掘必须写回来源**：从 L6 取出的结论都要标"出处（哪次会话 / 哪条沉淀）"。
5. **反向禁令**：⛔ 不能拿 L6 当"垃圾箱"。过程性垃圾**在入池前于源头丢弃**。
6. **容量红线 1 GB**，体检项 `l6_usage` 80%⚠ / 95%⛔。

自检类工具必须能证明"该失败时会失败"，结论要能说出**差异集合**。
报不出来 = 装的是装饰品。

## §10 项目本地化 · 项目信息 = 项目的唯一档案（2026-11-02 21:20 宿主立）

> **宿主原话（逐字，不可改写）**：
> 「会话是本地归档也是本地，一个场景就是做一个项目或者多个项目的；
>  比如客户运维系统场景里，本地文件居然一个都看不到！这些里面应该都是这个场景项目的文件；
>  比如主播自己的项目，有素材文件夹、任务清单文件夹、项目信息文件夹、database文件夹、
>  scripts文件夹、parent-uni-app文件夹、node_modules文件夹、docs文件夹等等等等；
>  这些都是要保存到本地的；
>  项目信息文件夹是重中之重，里面存储了各种会话md文件；
>  比如我做一个项目，每一个进程都是一个文档；
>  比如他的脚01_服务器信息.md；02_项目架构.md；等等等；
>  他是通过索引.md这个文件进行各种之前内容的查询；还有readme.md；
>  而且索引文件也不是要从上往下读完，而是搜索着找关键词；
>  注意这可不是沉淀层；而是项目信息；
>  只有重复的项目信息比如某两个会话重复了，那么删掉一个另一个进入沉淀层；
>  沉淀层本身就是只进不出做备份用的；而不是用来索引的」

### 10.1 ⛔ 三层分工（不许混）

| 层 | 是什么 | 在哪 | 只读还是可改 |
|---|---|---|---|
| **场景私有记忆** | 这个**场景**是谁、管什么、长期规矩 | `L2场景私有\<场景>\场景私有记忆.md` | 场景可写 |
| **项目信息** | 这个**项目**的全部档案（会话 md / 索引 / readme / 素材路径） | **项目自己的本地目录**（见 11.3） | 场景可写，**项目的唯一真源** |
| **L6 沉淀层** | **备份**：重复的项目信息、报废的会话原件 | `L6\池\` | ⛔ **只进不出，不做索引** |

**三条禁令（对应宿主原话最后三句）：**
1. ⛔ **项目信息 ≠ 沉淀层**。项目信息是活的、可查的、按关键词检索的；沉淀层是死的、只备份的。
2. ⛔ **不许把项目信息写进沉淀层当索引**。沉淀层不做索引。
3. ✅ **重复才入沉淀层**：两个会话/两份资料重复 ⇒ **删掉一份**，**另一份进沉淀层**（不是删两份、也不是都留着）。

### 10.2 一个场景 = 一个或多个项目，每个项目**必须**有自己的本地根目录

⛔ **硬要求**：任何场景的「本地文件」面板，打开后必须能看到**它自己项目的文件夹**。
实测反例（2026-11-02 宿主截图）：**客户系统运维** 场景的「本地文件」面板打开是 **空目录** ——
因为它绑的是 `D:\资料库`，而该目录 0 项。**这是违规，不是小毛病。**

**每个项目目录的标准形态（宿主举的例，按需取用，不强求全有）：**

```
<项目根>\
├─ 项目信息\                ← ★★★ 重中之重，见 11.3
│   ├─ 索引.md              ← 项目总索引（按关键词检索，⛔ 不许从头读到尾）
│   ├─ readme.md            ← 一页看懂：这个项目干什么、怎么跑、找谁
│   ├─ 01_服务器信息.md      ← 一个进程/一个主题 = 一个文档
│   ├─ 02_项目架构.md
│   ├─ 03_数据库.md
│   └─ …（编号递增，编号=阅读顺序）
├─ 素材\
├─ 任务清单\
├─ database\
├─ scripts\
├─ docs\
├─ parent-uni-app\
└─ node_modules\
```

- 目录名**用中英都行**，但**同一项目内必须一致**（不许一半中文一半英文）。
- `node_modules` / `dist` / `build` 这类**可再生产物**：可以存在，但 **⛔ 不进版本归档、⛔ 不进沉淀层**（白占容量）。

### 10.3 项目信息文件夹：`索引.md` + 一进程一文档

**规矩（宿主原话拆成可执行的四条）：**

1. **一个进程 = 一个文档**。做了什么动作，就有一个 `NN_<主题>.md`，编号递增。
   ⛔ 不许把所有事堆在一个大文件里（那会变成第二个"§五 无限膨胀"）。
2. **`索引.md` 是入口，不是正文**。每行一条：`NN_文件名.md — 一句话它解决什么 — 关键词`。
3. ⛔ **读索引不许从头读到尾**：必须**按关键词搜**（`grep` / 搜索框 / `findstr`）。
   理由：索引会长到几百行；从头读 = 每次白烧一个窗口的 5%。
4. **`readme.md` 是"外人第一次看"**：这个项目是什么 / 怎么跑起来 / 关键路径 / 谁负责。
   它和 `索引.md` 不重复：readme 讲**怎么用**，索引讲**去哪找**。

**索引.md 的模板（照抄即可）：**

```markdown
# <项目名> · 索引

> ⛔ 读这个文件请用搜索，不要从头读。关键词写在每行末尾。

| # | 文档 | 一句话 | 关键词 |
|---|---|---|---|
| 01 | 01_服务器信息.md | SSH / 端口 / 部署路径 | 服务器,ssh,部署 |
| 02 | 02_项目架构.md | 前后端分层、数据流 | 架构,分层,api |
```

### 10.4 场景 ↔ 项目 的绑定必须**在面板上看得见**

- 每个场景的 `file` 面板，`root` **必须**指向该场景的项目根（或项目根的父目录），
  ⛔ **不许留空**（留空就会退回默认 `D:\资料库`，而那是空目录 ⇒ 宿主看到"一个文件都没有"）。
- 一个新项目开工前，**先建目录 + 建 `项目信息\索引.md` + `readme.md`**，再开始写代码。
  ⛔ 不许"先干起来，文件最后补" —— 最后一定补不上。
- 项目建好后，**必须在 `_共享记忆\项目.json` 登记**（`node 工具\项目索引.mjs 登记`），
